## Microsoft Foundry: más modelos, agentes de voz y optimización continua
Microsoft publicó una entrada en su blog anunciando avances en Microsoft Foundry orientados a facilitar la construcción y operación de agentes empresariales. Las novedades incluyen soporte para una gama más amplia de modelos frontier (mencionan la familia GPT‑6 y Claude Opus 5.5 en el texto), la disponibilidad en preview de agentes de voz nativos en Foundry Agent Service y capacidades para ejecutar flujos de trabajo de larga duración con resiliencia. Además se enfatiza la instrumentación para convertir trazas de producción en datos de evaluación y optimización (insights, agent optimizer, rubric evaluator), y nuevas integraciones para gobernanza y control de agentes. En conjunto, el anuncio subraya el enfoque de Microsoft en ofrecer una pila completa para poner agentes en producción con observabilidad y controles empresariales.
[Fuente: Azure Blog — Ship agents faster with expanded model choice, voice agents, and continuous optimization.](https://azure.microsoft.com/en-us/blog/ship-agents-faster-with-expanded-model-choice-voice-agents-and-continuous-optimization/)

## Docker lanza Cloud Sandboxes para ejecutar agentes en la nube
Docker anunció Docker Cloud Sandboxes, una oferta destinada a ejecutar agentes de IA en infraestructuras gestionadas en la nube manteniendo aislamiento y políticas de seguridad. La solución extiende el modelo de sandbox local de Docker hacia un servicio cloud que permite despliegues continuos de sesiones agent‑centric, movilidad de entornos (mover del portátil a la nube) y mecanismos de gobernanza que viajan con el paquete. El comunicado destaca integración con flujos de trabajo de desarrollo y mecanismos para aislar la ejecución de código y herramientas usadas por agentes, orientado a reducir riesgo operativo al dejar agentes ejecutándose fuera del equipo del desarrollador.
[Fuente: Docker Press Release — Docker Launches Cloud Sandboxes.](https://www.docker.com/press-release/cloud-sandboxes-extending-secure-ai-agent-isolation-beyond-the-laptop/)

## Stand8 presenta Model Gateway para enrutar cargas AI en la empresa
Stand8 publicó un lanzamiento comercial del "Stand8 Model Gateway", una capa de control que se instala en la cuenta cloud del cliente (AWS/Azure/GCP) para enrutar tareas a distintos modelos según coste, latencia o requisitos de seguridad. El gateway aplica caching, políticas de identidad y auditoría, y pretende facilitar la transición de pruebas de concepto a producción mediante una oferta de entrega en 90 días. El planteamiento es gestionar la orquestación multi‑modelo sin introducir lock‑in en el proveedor del modelo, manteniendo controles y trazabilidad dentro del entorno del cliente.
[Fuente: PR Newswire — Stand8 Helps Enterprises Reduce AI Costs and Move from Pilot to Production.](https://www.prnewswire.com/news-releases/stand8-helps-enterprises-reduce-ai-costs-and-move-from-pilot-to-production-302889607.html)

## MSI presenta MS-C9ZA: mini-PC fanless con NVIDIA Jetson Orin Nano 8GB
MSI IPC presentó el MS‑C9ZA, un box PC compacto y sin ventilador basado en la plataforma NVIDIA Jetson Orin Nano (8 GB). ## Kubernetes v1.37: Pod-Level Resource Managers llega a Beta
La comunidad Kubernetes anunció que, con la línea 1.37, la característica Pod‑Level Resource Managers ha llegado al estado Beta (por defecto desactivada). La funcionalidad permite que componentes del nodo como el Topology Manager, CPU Manager y Memory Manager tomen decisiones de colocación basada en declaraciones de recursos al nivel de Pod en lugar de por contenedor, mejorando la colocación NUMA y soporte para workloads con sidecars. Es una mejora relevante para workloads cloud‑native con requisitos de latencia y alineamiento de recursos físicos.
[Fuente: Kubernetes Blog — Kubernetes v1.37: Pod‑Level Resource Managers graduated to Beta (15 Sep 2026).](https://kubernetes.io/blog/2026/09/15/kubernetes-v1-37-pod-level-resource-managers-beta/)

## Portainer y el cambio de foco hacia la edición empresarial y 3.x
Portainer ha ido moviendo su producto hacia un mayor enfoque empresarial con la próxima serie 3.x; en las últimas semanas se ha informado que la edición Community se mantendrá basada en la línea 2.45 LTS mientras que las novedades de 3.x apuntan a funciones y experiencia guiada para despliegues empresariales (Portainer‑Run, integraciones y features de gobernanza). Esto ha generado debate en la comunidad sobre la estrategia de producto y el impacto para usuarios de homelab y pequeñas instalaciones, por lo que conviene revisar la política de licencias y la oferta free para entornos con pocos nodos.
[Fuente: It's FOSS / Portainer coverage (septiembre 2026) — resumen del cambio hacia 3.x y CE freeze.](https://itsfoss.com/news/portainer-community-edition-freeze/)
