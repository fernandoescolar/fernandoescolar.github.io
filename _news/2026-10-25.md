## OpenAI: Scheduled Automations para Agents API
OpenAI anunció la incorporación de "Scheduled Automations" a la Agents API, una funcionalidad que permite programar la ejecución de sesiones de agentes mediante cron o timestamps únicos. Esto facilita escenarios donde agentes deben ejecutarse periódicamente (p. ej. comprobaciones diarias, informes automáticos o jobs de mantenimiento) sin orquestadores externos. La característica integra la programación con la configuración y el estado del agente, y permite invocar sesiones nuevas o reusar sesiones existentes según la configuración del proyecto. Fuente oficial: [OpenAI Developers — Scheduled automations (Agents API)](https://developers.openai.com/api/docs/guides/agents-api/sessions/automations). ([developers.openai.com](https://developers.openai.com/api/docs/guides/agents-api/sessions/automations?utm_source=openai))

## Azure: Decisions API disponible en Microsoft Foundry
Microsoft publicó guías y documentación para usar la Decisions API de Azure OpenAI dentro de Microsoft Foundry, indicando que la API (diseñada para evaluar condiciones y devolver respuestas tipadas como predicados, elecciones o puntuaciones) está disponible en las regiones donde el modelo compatible (ej. `gpt-6-luna`) está desplegado en Foundry. La integración está orientada a pipelines de decisión en aplicaciones y a flujos agenticos donde conviene evaluar opciones estructuradas en lugar de solo generar texto libre. La documentación incluye ejemplos de uso con SDKs y el endpoint `/openai/v1/decisions`. Fuente: documentación Microsoft Learn sobre Foundry y Decisions API. ([learn.microsoft.com](https://learn.microsoft.com/en-us/azure/foundry/openai/how-to/decisions?utm_source=openai))

## Azure: Mitigación Brotli (CVE-2026-111497) con WAF
Microsoft publicó recomendaciones para proteger aplicaciones frente a la vulnerabilidad en la implementación de Brotli (CVE-2026-111497), incluyendo la configuración de Azure Web Application Firewall (WAF) como medida mitigadora. El aviso detalla cómo la WAF puede ayudar a bloquear vectores de explotación y sugiere revisar componentes y runtimes expuestos que dependan de versiones vulnerables de Brotli, además de aplicar parches en la pila de aplicaciones. Estas guías fueron difundidas en los blogs técnicos de Azure el 23 de octubre. Fuente: comunicaciones oficiales de blogs Microsoft/Azure (oct 23, 2026). ([techcommunity.microsoft.com](https://techcommunity.microsoft.com/Blogs?utm_source=openai))

## Azure Functions: actualizaciones de zona horaria y runtimes
El equipo de App Service/Azure Functions anunció el despliegue de imágenes y parches para actualizar las reglas de zona horaria (IANA 2026e) y actualizaciones urgentes en runtimes (Node.js, Python) así como una corrección relacionada con certificados eMudhra / emSign. Las actualizaciones se están aplicando por canales de plataforma y los equipos recomiendan mover apps al canal `Latest` para recibir los cambios lo antes posible, además de revisar dependencias de runtimes en funciones que usan workers específicos. Fuente: Azure App Service blog — actualizaciones desplegadas el 22–23 de octubre. ([azure.github.io](https://azure.github.io/AppService/2026/10/23/time-zone-runtime-certificate-updates-azure-functions.html?utm_source=openai))

## Docker Engine y componentes: correcciones y CVE recientes
Las notas públicas de lanzamientos de Docker Engine incluyen arreglos recientes que abordan múltiples vulnerabilidades, entre ellas problemas de validación TLS al conectar con registries, correcciones en BuildKit (cache poisoning), y actualizaciones de `containerd`. Los mantenedores han publicado versiones parcheadas y descripciones de CVE resueltas; operadores de clústeres y entornos self-hosted deben planificar la actualización y validar imágenes base tras aplicar parches. Fuente: índice de release notes de Docker (octubre 2026). ([releases.sh](https://releases.sh/docker?utm_source=openai))

## PHP «PHP2Shell» y su impacto en NAS / contenedores
Se han publicado informes y avisos sobre una vulnerabilidad crítica en PHP (apodada PHP2Shell) que ha afectado a imágenes Docker y a dispositivos NAS con PHP embebido; varios proveedores y ecosistemas han liberado imágenes corregidas o instrucciones para mitigar el impacto. La recomendación general para administradores de homelab es revisar imágenes base, actualizar PHP en contenedores y aplicar parches del fabricante del NAS cuando estén disponibles. Artículos de divulgación técnica y posts comunitarios describen la coordinación de parches entre proveedores. Fuente: cobertura técnica (TechRadar) y anuncios de la comunidad (23–24 oct). ([techradar.com](https://www.techradar.com/pro/security/php-security-issues-could-also-threaten-your-nas-device-but-not-every-vendor-is-able-to-patch-just-yet?utm_source=openai))

## Amazon Linux (ALAS): advisory ALAS2DOCKER-2026-155
Amazon Linux 2 publicó un advisory (ALAS2DOCKER-2026-155) relacionado con componentes Docker en sus repositorios; el advisory instruye a ejecutar `yum update docker` o aplicar la actualización específica del advisory para corregir problemas señalados. Los usuarios de AMI/instancias que dependan de paquetes del repositorio oficial deben actualizar cuanto antes para cerrar la ventana de exposición. Fuente: anuncio ALAS (ALAS2DOCKER-2026-155, 24 oct 2026). ([alas.aws.amazon.com](https://alas.aws.amazon.com/AL2/ALAS2DOCKER-2026-155.html?utm_source=openai))
