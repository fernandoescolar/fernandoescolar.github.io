## NVIDIA lanza PAIR: enrutador personal para inferencia local
NVIDIA presentó PAIR (Personal AI Router), una herramienta para agrupar sistemas locales con GPUs compatibles y enrutar peticiones de inferencia dentro de una red doméstica o de oficina pequeña, con el objetivo de aprovechar ciclos inactivos y distribuir cargas de agentes o modelos ligeros. PAIR ofrece un plano de control local (servicios en Go y proxies HTTP) que detecta nodos disponibles, consulta qué modelos están cacheados y envía trabajos al nodo idóneo, manteniendo el tráfico dentro de la red local. La iniciativa busca facilitar despliegues de IA local, reducir dependencia de la nube para inferencia y ofrecer una ruta práctica para ejecutar agentes y cargas de ML en infraestructuras domésticas o de oficina.  
Fuente: [NVIDIA — Personal AI Router (PAIR) overview](https://www.nvidia.com/en-eu/ai-on-rtx/personal-ai-router/). ([nvidia.com](https://www.nvidia.com/en-eu/ai-on-rtx/personal-ai-router/?utm_source=openai))

## Docker define “YOLO mode” y recomienda límites seguros
Docker publicó un artículo que acuña y explica el término "YOLO mode" para describir cuando un agente de IA ejecuta acciones sin pedir aprobación humana (auto‑aprobar todo). El texto enumera riesgos claros —comandos destructivos, exposición de credenciales, exfiltración— y propone que la solución no es más o menos permisos sino ejecutar agentes dentro de límites bien definidos: sandboxes efímeros, microVMs o ambientes aislados sin secretos. Docker relaciona la práctica con su propia oferta de Docker Sandboxes y con herramientas de gobernanza para agentes, y recomienda políticas organizativas para que la autonomía sea segura en equipo.  
Fuente: [Docker Blog — YOLO Mode: Agent Autonomy Without the Guardrails](https://www.docker.com/blog/what-is-yolo-mode/). ([docker.com](https://www.docker.com/blog/what-is-yolo-mode/?utm_source=openai))

## Azure y AWS: interconexión multicloud gestionada
Microsoft describió Azure Multicloud Interconnect for AWS, una propuesta para ofrecer conectividad privada gestionada entre Azure y AWS usando especificaciones Open API para interoperabilidad. La solución pretende simplificar la provisión de enlaces privados de alto ancho de banda (hasta 100 Gbps en GA según la nota), integrando la experiencia de aprovisionamiento y ofreciendo controles de seguridad y disponibilidad pensados para cargas multicloud y aplicaciones de IA que mueven datos entre proveedores. Microsoft publica guías técnicas e indica que la colaboración se apoya en AWS Interconnect – multicloud del lado de AWS.  
Fuente: [Microsoft Azure Blog — Introducing Azure Multicloud Interconnect for AWS](https://azure.microsoft.com/en-us/blog/introducing-azure-multicloud-interconnect-for-aws/). ([azure.microsoft.com](https://azure.microsoft.com/en-us/blog/introducing-azure-multicloud-interconnect-for-aws/))
