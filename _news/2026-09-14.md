## OpenAI: Agents API (public beta)
OpenAI ha lanzado en beta pública la nueva Agents API, que ofrece la infraestructura gestionada (el "harness" de Codex) para crear, ejecutar y orquestar agentes con herramientas, memoria y gestión de sesiones prolongadas.  
La API permite declarar tareas, modelos y herramientas en una sola llamada y ofrece manejo integrado de context compaction, ejecución paralela de herramientas y sandboxes administrados. Esta apertura facilita a desarrolladores construir agentes productivos sin implementar desde cero la orquestación de memoria y seguridad.  
[Fuente: OpenAI - Introducing the Agents API]. ([openai.com](https://openai.com/index/introducing-the-agents-api/?utm_source=openai))

## OpenAI: GPT‑6 "Astra" — despliegue y fichas de seguridad
OpenAI continúa la implantación de GPT‑6 (codenombrado "Astra") y ha publicado fichas de seguridad y notas sobre mitigaciones de explotación y robustez.

## Google Cloud: MCP en API Gateway y mejoras en Vertex AI / BigQuery
Las notas de producto de Google Cloud recogen novedades publicadas recientemente: API Gateway añade la posibilidad de actuar como servidor remoto del Model Context Protocol (MCP) en vista previa, facilitando exponer APIs REST como herramientas para agentes; además BigQuery amplía funciones generativas y Vertex AI sigue incorporando capacidades de agente y búsquedas vectoriales.  
Estas actualizaciones refuerzan el enfoque de Google en integrar herramientas para agentes y flujos RAG en la plataforma de datos y ML gestionados.  
[Fuente: Google Cloud Release Notes (septiembre 2026)]. ([docs.cloud.google.com](https://docs.cloud.google.com/release-notes?authuser=01&utm_source=openai))

## Kubernetes v1.37: etcd RangeStream y otras mejoras relevantes
Kubernetes 1.37 incluye la graduación a beta de `EtcdRangeStream`, que permite lecturas por streaming desde etcd para reducir picos de memoria en lecturas de colecciones grandes; además se promocionan mejoras en Dynamic Resource Allocation (DRA) y otras API que facilitan gestión de recursos especializados (por ejemplo GPUs/accelerators).  
La nota oficial del proyecto describe cómo RangeStream reduce el uso de memoria tanto en etcd como en el kube-apiserver y los requisitos (etcd v3.7+), y enumera la lista de características promovidas en 1.37.  
[Fuente: Blog de Kubernetes — v1.37 release & RangeStream]. ([kubernetes.io](https://kubernetes.io/blog/2026/09/01/kubernetes-v1-37-etcd-range-stream/?utm_source=openai))

## Docker Engine v29.8.0: nuevo flag `--umask` y mejoras de seguridad
Docker publicó las notas de la serie Engine 29; la versión `29.8.0` (publicada en septiembre) añade la opción `HostConfig.Umask` y el flag `--umask` para `docker create` / `docker run`, permitiendo fijar el umask del proceso principal del contenedor y de ejecuciones/healthchecks.  
La release también introduce mejoras de registro (awslogs), controles AppArmor/SELinux adicionales y correcciones de seguridad. Es recomendable revisar notas si gestiona flotas de contenedores con políticas de permisos estrictas.  
[Fuente: Docker Engine release notes v29 (29.8.0)]. ([docs.docker.com](https://docs.docker.com/engine/release-notes/29/?utm_source=openai))

## Go 1.27: lanzamiento oficial y cambios clave
El equipo de Go publicó Go 1.27 (lanzamiento oficial en agosto, con revisiones posteriores en septiembre). Entre los cambios más relevantes están el soporte para métodos genéricos, `encoding/json/v2`, mejoras en el runtime y nuevas utilidades en `go fix` y `go doc`.  
La entrada oficial y las notas de la versión contienen detalles completos; es una actualización importante para proyectos que aprovechan genéricos y mejoras del toolchain.  
[Fuente: Go Blog / Go 1.27 release notes]. ([go.dev](https://go.dev/blog/go1.27?utm_source=openai))

## Azure Functions (Flex Consumption): soporte TLS/SSL por aplicación y cifrado end‑to‑end
Microsoft ha publicado (y actualizado en la documentación) el soporte para certificados TLS/SSL por app en el plan Flex Consumption de Azure Functions, además de la opción de cifrado end‑to‑end entre frontends de plataforma y workers.  
Esto permite subir/importar hasta un número limitado de certificados por Function App (incluyendo Key Vault) y facilita escenarios de mTLS y dominios personalizados en entornos serverless. Revisar la guía de Microsoft Learn para procedimientos y límites.  
[Fuente: Microsoft Learn / documentación Azure Functions Flex Consumption]. ([learn.microsoft.com](https://learn.microsoft.com/en-sg/azure/azure-functions/flex-consumption-plan?utm_source=openai))

## Microsoft MSRC: ampliación de VEX para cobertura de CVEs
Microsoft Security Response Center (MSRC) publicó información sobre la ampliación del intercambio Machine-readable Vulnerability Exploitability eXchange (VEX) para cubrir más CVEs y mejorar la trazabilidad de mitigaciones en el ecosistema.  
La iniciativa busca mayor transparencia en información de explotación y estado de mitigación para CVEs de Microsoft, lo que impacta especialmente a equipos de cloud y devops que gestionan parches y cumplimiento.  
[Fuente: MSRC blog — Toward greater transparency: Expanding VEX]. ([microsoft.com](https://www.microsoft.com/en-us/msrc/blog/2026/09/toward-greater-transparency-expanding-machine-readable-vulnerability-exploitable-exchange?utm_source=openai))
