## NVIDIA lanza la Open Agent Safety Platform
NVIDIA presentó una plataforma abierta para seguridad de agentes que combina un runtime de contención y un sistema de vigilancia en hardware. La oferta, llamada NVIDIA Open Agent Safety Platform, incluye OpenShell (runtime abierto que aísla y aplica políticas a agentes) y Sentry (referencia de sistema que usa DPUs BlueField‑4 para monitorización fuera de banda y capacidad de cuarentena instantánea). La compañía apunta a ofrecer controles tanto a nivel de software como a nivel hardware para detener comportamientos fuera de la política en milisegundos, y ya anuncia integraciones con algunos socios empresariales. El lanzamiento busca responder a la creciente preocupación por agentes que realizan acciones no autorizadas y propone un enfoque de seguridad en capas —runtime seguro + vigilancia en silicio— para entornos empresariales y de robótica. [Fuente](https://nvidianews.nvidia.com/news/open-agent-safety-platform). ([nvidianews.nvidia.com](https://nvidianews.nvidia.com/news/open-agent-safety-platform?utm_source=openai))

## Blazor AI: nuevos componentes para UI agentiva en .NET
Microsoft publicó un artículo detallado sobre nuevos componentes experimentales de Blazor diseñados para construir interfaces "agentivas" (Agentic UI). Los componentes facilitan renderizar interacciones de agentes en streaming, manejar bloques de contenido observables, presentar llamadas a herramientas, solicitudes de aprobación y compartir estado tipado entre la UI y el agente. El post explica integración con Microsoft.Extensions.AI, el SDK AG‑UI .NET y el Microsoft Agent Framework, y aporta un ejemplo completo (AgenticUI) que muestra cómo exponer endpoints AG‑UI desde ASP.NET Core y consumirlos desde Blazor. La funcionalidad está en preview/exploratoria y permite a desarrolladores combinar control UI tradicional con interacción multistep de agentes. [Fuente](https://devblogs.microsoft.com/dotnet/build-agentic-ui-blazor/). ([devblogs.microsoft.com](https://devblogs.microsoft.com/dotnet/build-agentic-ui-blazor/?utm_source=openai))

## GCP anuncia la familia Z4D storage‑optimized (GA)
Google Cloud anunció la disponibilidad general de la familia de máquinas storage‑optimized Z4D para Compute Engine, con opciones VM y bare‑metal. Las Z4D están orientadas a cargas IO‑intensivas (bases de datos SQL/NoSQL, bases de vectores y cargas de entrenamiento/serving para ML) y ofrecen hasta 84 TiB de Local SSD, con mejoras de rendimiento frente a la generación anterior. Google señala que estas instancias están pensadas para casos que requieren gran capacidad y throughput de almacenamiento local, incluyendo sistemas distribuidos y datastores de baja latencia. La nota incluye detalles de CPUs (AMD EPYC Turin) y escenarios recomendados. [Fuente](https://cloud.google.com/blog/products/compute/storage-optimized-z4d-vm-and-bare-metal-instances). ([cloud.google.com](https://cloud.google.com/blog/products/compute/storage-optimized-z4d-vm-and-bare-metal-instances?utm_source=openai))

## Google Earth Engine integra "Ask" con Gemini para geoespacial
Google Cloud anunció una nueva función llamada "Ask" en Google Earth Engine que integra capacidades de Gemini dentro del editor de Earth Engine para acelerar la codificación geoespacial. "Ask" ayuda a traducir consultas de análisis geoespacial a scripts, reduciendo la necesidad de memorizar API y acelerando prototipos para análisis de cobertura forestal, cambios en infraestructura o detección agrícola. El artículo destaca cómo esta integración mejora la productividad para científicos de datos y equipos que trabajan con grandes colecciones de datos geoespaciales. [Fuente](https://cloud.google.com/blog/products/data-analytics/accelerate-geospatial-coding-with-ai-in-google-earth-engine). ([cloud.google.com](https://cloud.google.com/blog/products/data-analytics/accelerate-geospatial-coding-with-ai-in-google-earth-engine?utm_source=openai))

## Model Armor de GCP añade reglas de exclusión específicas por plantilla (preview)
Las notas de release de Model Armor (Google Cloud) indican que se ha añadido una función en preview: reglas de exclusión específicas por plantilla. Esta mejora permite configurar listas de palabras/frases y expresiones regulares para reducir falsos positivos en detección de inyección de prompt y filtros de IA responsable, aplicando excepciones por plantilla. Es una herramienta pensada para ajustar detección en pipelines RAG y sistemas de moderación contextual cuando el comportamiento legítimo del dominio provoca alertas recurrentes. [Fuente](https://docs.cloud.google.com/model-armor/release-notes). ([docs.cloud.google.com](https://docs.cloud.google.com/model-armor/release-notes?utm_source=openai))
