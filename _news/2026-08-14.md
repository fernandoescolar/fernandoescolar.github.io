## Routing y failover para Microsoft.Extensions.AI
Microsoft ha publicado un artículo técnico que introduce nuevas primitivas experimentales en `Microsoft.Extensions.AI` para enrutar peticiones entre clientes de chat y añadir políticas de failover. Las nuevas abstracciones —`RoutingChatClient`, `SemanticRoutingChatClient`, `FailoverChatClient` y `OrderedFailoverChatClient`— permiten decidir dinámicamente qué proveedor o modelo usar por mensaje, basarse en similitud semántica para seleccionar rutas, y reenviar automáticamente a clientes alternativos cuando se producen fallos antes de exponer salida al usuario. El diseño enfatiza opciones por petición frente a opciones por cliente, técnicas para “sticky selection” (mantener una ruta por sesión), métricas observables (p. ej. tiempo hasta la primera actualización) para circuit breaking, y patrones para combinar coste, latencia y capacidades al elegir modelos. [Fuente: devblogs.microsoft.com/dotnet]. ([devblogs.microsoft.com](https://devblogs.microsoft.com/dotnet/routing-and-failover-for-microsoft-extensions-ai/))

## Instrucciones: higiene para modelos frontera
Microsoft publicó una guía sobre “instructions hygiene” para equipos que usan modelos frontera: recomienda mantener los ficheros de instrucciones compactos, con la mínima información que sea específica, crítica y difícil de inferir por el modelo —por ejemplo límites del sistema, comandos de validación fiables y decisiones de diseño locales— y eliminar rutinas obsoletas o detalles que las herramientas ya imponen. El artículo describe qué incluir (hechos no obvios, camino más corto a la validación, restricciones costosas) y qué evitar (consejos genéricos, inventarios exhaustivos, rituales de prompting). También propone prácticas de revisión (keep/remove/move/verify) para que las instrucciones evolucionen con las capacidades del modelo. [Fuente: devblogs.microsoft.com/dotnet]. ([devblogs.microsoft.com](https://devblogs.microsoft.com/dotnet/instructions-hygiene-what-frontier-models-still-need-you-to-say/))

La página oficial de descargas de Go muestra disponibles los paquetes de `go1.26.6` (builds y binarios para múltiples plataformas) y también de `go1.25.13` para las ramas mantenidas. ## Gemini Enterprise Agent Platform: novedades (resumen)
Google Cloud resume mejoras y disponibilidad de varias capacidades del Gemini Enterprise Agent Platform orientadas a despliegue empresarial. Entre las funcionalidades destacadas están: Agent Memory Bank para mantener esquemas de memoria estructurada y personalización de agentes; Agent Runtime para ejecutar agentes de larga duración (hasta varios días); Agent Identity, Agent Gateway y Agent Registry para identidades, gobernanza y catálogo centralizado de agentes; y herramientas de observabilidad y evaluación continua de comportamiento agente. El post enfatiza controles IAM nativos para agentes y capacidades para auditar y evaluar decisiones en producción, y ofrece casos de uso y testimonios de clientes. [Fuente: cloud.google.com/blog]. ([cloud.google.com](https://cloud.google.com/blog/products/ai-machine-learning/whats-new-in-gemini-enterprise-agent-platform))

## Developer Device Platform para apps móviles agenticas
Google Cloud anunció el Developer Device Platform (DDP), una iniciativa que facilita el desarrollo y prueba de apps móviles con capacidades agenticas, orientada a probar interacciones y rendimiento en dispositivos reales. DDP busca cerrar la brecha entre desarrollo local y despliegue en dispositivos, proporcionando herramientas para ejecución y pruebas de agentes que integran sensores, cámaras y modelos multimodales en móviles. Es relevante para equipos que construyen agentes que dependen de datos de dispositivo y necesitan validar experiencia y latencia en hardware heterogéneo. [Fuente: cloud.google.com/blog]. ([cloud.google.com](https://cloud.google.com/blog/topics/developers-practitioners/announcing-developer-device-platform-on-google-cloud))

## Gateway API v1.6: TCPRoute y UDPRoute llegan a Standard
El proyecto Gateway API ha publicado la entrada sobre la versión v1.6 donde `TCPRoute` y `UDPRoute` han alcanzado estatus Standard. La evolución amplía oficialmente las capacidades del Gateway API para protocolos de capa de transporte y simplifica el enrutado de tráfico TCP/UDP a aplicaciones dentro del clúster. Esto impacta a implementaciones cloud-native y a controladores (ingress/mesh) que podrán aprovechar rutas estandarizadas para cargas no HTTP, reduciendo la necesidad de soluciones específicas por proveedor. Revisa la entrada para detalles de compatibilidad y prácticas recomendadas al migrar reglas de red a Gateway API. [Fuente: kubernetes.io/blog]. ([kubernetes.io](https://kubernetes.io/blog/2026/08/03/gateway-api-v1-6-release/))
