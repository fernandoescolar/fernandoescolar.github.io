## OpenAI añade primitivas para la Responses API con GPT‑6 Astra
OpenAI ha publicado cambios recientes en la familia Astra de modelos y en la Responses API que introducen tres primitivas pensadas para flujos de trabajo de larga ejecución y control fino: llamadas asíncronas a funciones (async function calling) para permitir que el modelo continúe razonando mientras la aplicación ejecuta herramientas externas; la capacidad de "dirigir" una respuesta en curso (mid‑turn steering) enviando instrucciones adicionales durante un streaming por WebSocket; y controles de "esfuerzo de razonamiento" que permiten ajustar cómo se usa la caché de prompts sin invalidarla. Estas funciones están orientadas a integraciones que necesitan manejar tareas de larga duración, corregir salidas mientras el modelo está produciendo texto y conservar eficiencia en escenarios con caché de prompts. La documentación oficial de modelos y la guía de la Responses API han sido actualizadas para reflejar estas opciones y su uso en proyectos que usen GPT‑6 Astra. [Fuente](https://developers.openai.com/api/docs/guides/latest-model).

## Docker Desktop 4.90.0: actualización y correcciones (incluye parche CVE)
Docker publicó las notas de la versión 4.90.0 el 7 de septiembre de 2026. El release incluye mejoras generales en la experiencia del escritorio, actualizaciones de componentes (Docker Agent, Docker Offload, CLI y Buildx) y varias correcciones de errores. Además, esta versión menciona correcciones relacionadas con vulnerabilidades de seguridad en componentes de inferencia ML (se indica tratamiento para un CVE en el backend de inferencia) y mejoras en diagnósticos integrados (nuevo tracker de incidencias y acceso a "Ask Gordon" desde la UI). Se recomienda actualizar Docker Desktop en entornos de desarrollo para beneficiarse de las correcciones y mitigaciones incluidas. [Fuente](https://docs.docker.com/desktop/release-notes/).

## GCP publica aviso de seguridad (GCP‑2026‑060) sobre Slurm – parche disponible
El 7 de septiembre de 2026 Google Cloud publicó un boletín de seguridad (GCP‑2026‑060) relacionado con una vulnerabilidad en la herramienta Slurm `sbcast` (CVE-2026-65107). Google indica que las imágenes de SO gestionadas por Cluster Toolkit se han actualizado con parches y da instrucciones de mitigación: recrear o redeplegar nodos con la imagen parcheada o actualizar blueprints y reinstanciar. El aviso incluye pasos concretos para clusters HPC que usan Slurm y subraya que si un nodo no se ha recreado desde el 7 de septiembre, puede seguir siendo vulnerable. Administradores de clusters en GCP deberían aplicar las recomendaciones cuanto antes. [Fuente](https://cloud.google.com/cluster-toolkit/docs/security-bulletins).

## Microsoft Entra: SSPR exige métodos registrados a partir del 7 de septiembre (enforcement)
Microsoft recuerda que el cambio para Self‑Service Password Reset (SSPR) que exige métodos de verificación expresamente registrados entró en enforcement el 7 de septiembre de 2026. Tras la fecha de aplicación, Entra ID sólo aceptará métodos de autenticación que los usuarios hayan registrado explícitamente (p. ej. Authenticator, FIDO2, SMS si está registrado), y la información de contacto sincronizada con el directorio ya no servirá por sí sola para realizar una SSPR. Microsoft lanzó campañas de registro automáticas desde julio y ofrece guías para administradores para identificar usuarios sin métodos registrados y evitar interrupciones. Recomendado: validar inventario de métodos registrados y comunicar a usuarios finales antes de la expiración. [Fuente](https://techcommunity.microsoft.com/tag/announcements%20and%20product%20news).

## Equinix anuncia servicios de conectividad para infraestructuras AI distribuidas
Equinix presentó el 8 de septiembre de 2026 nuevas capacidades de conectividad dirigidas a desplegar infraestructuras AI distribuidas: servicios que facilitan interconexión optimizada, rutas de baja latencia y opciones de cifrado y resiliencia pensadas para arquitecturas híbridas que conectan nubes públicas, centros de datos y edge. El anuncio está orientado a empresas que migran cargas AI a producción y necesitan gestionar conectividad entre silos (multi-cloud y on‑prem). Para equipos de infra y redes que planifican despliegues de inferencia o entrenamiento distribuido, estas opciones pueden simplificar el diseño de red y los requisitos de cumplimiento. [Fuente](https://futureiot.tech/equinix-targets-ai-infrastructure-complexity-with-new-connectivity-services/).

## Sinology / Synology Assistant: recordatorio de la CVE-2026-4793 y parches recomendados
Se recuerda la existencia de la vulnerabilidad identificada como CVE‑2026‑4793 en Synology Assistant (incorrect default permissions) y la disponibilidad de un advisory oficial con versiones afectadas y la recomendación de actualizar a las builds parcheadas (Synology Assistant < 7.0.7‑50095 estaba afectado). Varias fuentes de seguridad y bases CVE recogen la entrada y remiten al advisory oficial de Synology donde están los pasos de actualización y mitigación; los administradores de NAS deben verificar versiones y aplicar los parches proporcionados por Synology para evitar que un usuario local pueda leer/ escribir archivos arbitrarios durante instalaciones. [Fuente](https://www.synology.com/en-global/security/advisory/Synology_SA_26_12).
